1. What is GitHub Actions?

GitHub Actions is a free tool built into GitHub that runs tasks for you automatically. Think of it like a robot assistant that lives in your repository. You tell it what to do, when to do it, and it does the work — no one has to click a button.

Common jobs for authors:

  • Build your book site every time you push a new chapter.
  • Run checks on pushes (links, spelling, formatting).
  • Deploy to GitHub Pages so your book is live on the web for free.
  • Handle secrets safely (API keys, publishing tokens) without ever pasting them into a file.

All of this is defined in a YAML file — a plain-text format that looks like a list with indentation. If you can write an email, you can write YAML.

Where workflow files live: In a folder called .github/workflows/ inside your repository. Each .yml or .yaml file there is one automated job.

2. Your first workflow: "Hello, book"

Create .github/workflows/hello.yml in your repository:

name: Hello, book

on:
  push:
    branches: [ main ]

jobs:
  greet:
    runs-on: ubuntu-latest
    steps:
      - name: Say hello
        run: echo "Hello from your book site!"
LineMeaning
name:A friendly name shown on the GitHub Actions tab.
on:The event that starts the workflow. push means "when code is pushed."
branches:Only run on the main branch.
jobs:A group of tasks.
runs-on:The computer GitHub provides. ubuntu-latest is standard.
steps:The list of actions to do, in order.
run:A shell command to execute.

Push this file to GitHub, then open your repository's Actions tab. You should see your workflow run and print Hello from your book site!

3. Auto-build a book site

This workflow converts your Markdown (`.md`) files into HTML every time you push, saving them in a _site/ folder.

name: Build book site

on:
  push:
    branches: [ main ]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Check out repository
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"

      - name: Install a Markdown converter
        run: pip install markdown

      - name: Build HTML from Markdown
        run: |
          mkdir -p _site
          for file in *.md; do
            [ -e "$file" ] || continue
            python -m markdown "$file" > "_site/${file%.md}.html"
          done

      - name: Upload site as artifact
        uses: actions/upload-artifact@v4
        with:
          name: book-site
          path: _site

How it works

actions/checkout@v4 downloads your repository. actions/setup-python@v5 installs Python. The run: block converts every `.md` file to HTML in `_site/`. The artifact step saves the built site so you can download or deploy it.

4. Run checks on pushes

Automatic checks catch problems early. This example verifies Markdown files have titles and that no file is too large.

name: Run checks

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - name: Check out repository
        uses: actions/checkout@v4

      - name: Check Markdown files have titles
        run: |
          for file in *.md; do
            [ -e "$file" ] || continue
            if ! head -1 "$file" | grep -q '^# '; then
              echo "::error file=$file::Missing title (start with # Title)"
              exit 1
            fi
          done

      - name: Check no file is too large
        run: |
          big=$(find . -type f -size +5M -not -path './.git/*' | head -n 1)
          if [ -n "$big" ]; then
            echo "::error::File too large: $big"
            exit 1
          fi

Runs on both push and pull_request. If a step exits with exit 1, GitHub shows a red X, protecting your main branch from broken changes.

5. Deploy to GitHub Pages

GitHub Pages hosts your site for free. This workflow builds your site and publishes it automatically.

name: Deploy to GitHub Pages

on:
  push:
    branches: [ main ]

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Check out repository
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"

      - name: Install Markdown converter
        run: pip install markdown

      - name: Build HTML site
        run: |
          mkdir -p _site
          for file in *.md; do
            [ -e "$file" ] || continue
            python -m markdown "$file" > "_site/${file%.md}.html"
          done

      - name: Upload Pages artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: _site

      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
Before you deploy: In your repository on GitHub, go to Settings → Pages. Under "Build and deployment," set Source to "GitHub Actions."

The first time you push this workflow, GitHub creates a deployment. After it finishes, your site is live at https://yourusername.github.io/your-repo/. Every push rebuilds and redeploys it.

6. Safe secrets handling

Never put passwords, API keys, or tokens in a YAML file. Anyone who can see your repository can see the file.

The right way: Store the secret in GitHub (Settings → Secrets and variables → Actions), then reference it in your workflow:

      - name: Publish to book store
        run: echo "Publishing with key of length ${#BOOK_STORE_API_KEY}"
        env:
          BOOK_STORE_API_KEY: ${{ secrets.BOOK_STORE_API_KEY }}
DoDon't
Store secrets in GitHub's secret settingsPaste secrets into YAML files
Use ${{ secrets.SECRET_NAME }} only inside env:Log or print secret values
Use different secrets for different repositoriesReuse one personal key everywhere

For deploys, use a GitHub Environment (like github-pages above). Environments can require approval before a workflow runs, so a deploy doesn't happen until someone clicks "Approve."

Troubleshooting

ProblemWhat to try
Workflow doesn't appearCheck the file is in .github/workflows/ and ends in .yml or .yaml.
Red X on a runClick the run in the Actions tab, then click the failed step to see its logs.
"Permission denied" deployingGo to Settings → Pages and set the source to "GitHub Actions."
Secret not foundMake sure the secret name matches exactly (case-sensitive).
